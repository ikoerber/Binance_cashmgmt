## Phase Details

### Phase 23: Navigation Structure
**Goal**: User sees consistent sub-navigation on every page in the application
**Depends on**: Nothing (structural change, foundation for other phases)
**Requirements**: NAV-01
**Success Criteria** (what must be TRUE):
  1. User sees the Trading/Analyse/Bot/Admin sub-navigation groups when visiting the Settings page
  2. User sees the sub-navigation groups when visiting the Status Dashboard page
  3. User sees the sub-navigation groups when visiting the Backtest page
  4. All three pages render inside SymbolLayout with proper symbol context in the URL
**Plans**: 1 plan

Plans:
- [ ] 23-01: Move Settings, Status, Backtest inside SymbolLayout + sub-nav restructure + URL redirects

### Phase 24: Dynamic Symbol Visibility
**Goal**: User only sees symbols they actually hold, reducing noise from empty positions
**Depends on**: Phase 23 (navigation structure must be stable before filtering symbols)
**Requirements**: NAV-02, NAV-03
**Success Criteria** (what must be TRUE):
  1. User who holds BTC and XRP but no ETH sees only BTCEUR and XRPEUR in the GlobalNav symbol switcher
  2. User who holds all three assets sees all three symbols in GlobalNav
  3. Overview page only displays cards for symbols with a positive Binance balance
  4. A backend endpoint returns the list of symbols with positive balances (querying Binance account)
**Plans**: 1 plan

Plans:
- [ ] 24-01: Backend active-symbols endpoint + frontend hook + GlobalNav/Overview/SymbolLayout filtering

### Phase 25: Dedicated Chart Page
**Goal**: User can view a full-page interactive candlestick chart for the current symbol
**Depends on**: Phase 23 (chart page lives inside SymbolLayout)
**Requirements**: CHART-01, CHART-02, CHART-07
**Success Criteria** (what must be TRUE):
  1. User can navigate to a "Chart" page from the Trading nav group for the current symbol
  2. User can switch between 1h, 4h, and 1d intervals and adjust the lookback period
  3. Chart displays OHLCV candlesticks with a volume histogram below the price area
  4. Chart is full-page width and uses the existing lightweight-charts library with dark theme
**Plans**: TBD

Plans:
- [ ] 25-01: Chart page route, component, and candle data integration
- [ ] 25-02: Interval/lookback controls and volume histogram

### Phase 26: Chart Overlays
**Goal**: User can see all relevant trading context (zones, break-even, orders, trailing stops) directly on the chart
**Depends on**: Phase 25 (base chart must exist)
**Requirements**: CHART-03, CHART-04, CHART-05, CHART-06
**Success Criteria** (what must be TRUE):
  1. User can see orderblock zones rendered as shaded rectangular overlays on the chart
  2. User can see their portfolio break-even price as a labeled horizontal line
  3. User can see open sell order prices as horizontal lines (distinct from break-even)
  4. User can see active trailing stop levels on the chart when dry-run or bot is active
  5. Each overlay type is visually distinguishable (different colors/styles)
**Plans**: TBD

Plans:
- [ ] 26-01: Orderblock zone overlays and break-even line
- [ ] 26-02: Sell order lines and trailing stop levels

### Phase 27: Overview Improvements
**Goal**: User gets a clear, consolidated view of all holdings including BNB fee status
**Depends on**: Phase 24 (dynamic symbol filtering affects which cards appear)
**Requirements**: OVER-01, OVER-02, OVER-03
**Success Criteria** (what must be TRUE):
  1. Overview displays one consolidated card per crypto asset (BTC, ETH, XRP) instead of per trading pair
  2. User can see their BNB balance and its current EUR value in the Overview
  3. User can see recent BNB fee deductions showing how much BNB was consumed by recent trades
  4. BNB is displayed as a non-tradable balance card (no lots, orders, or pairing actions)
**Plans**: TBD

Plans:
- [ ] 27-01: Consolidated asset cards and BNB balance display
- [ ] 27-02: BNB fee deduction history

### Phase 28: Backtest Explainer
**Goal**: User understands what Walk-Forward backtesting does and what each parameter controls
**Depends on**: Phase 23 (Backtest page must be inside SymbolLayout)
**Requirements**: OVER-04, OVER-05
**Success Criteria** (what must be TRUE):
  1. Backtest page has an expandable explainer section describing Walk-Forward methodology
  2. Explainer covers key concepts: in-sample/out-of-sample split, rolling windows, overfitting prevention
  3. Each parameter input on the Backtest page has a description tooltip or inline text explaining what it controls
**Plans**: TBD

Plans:
- [ ] 28-01: Walk-Forward explainer and parameter descriptions
