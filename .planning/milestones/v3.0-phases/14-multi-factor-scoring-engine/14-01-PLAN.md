  <behavior>
    ## Dataclasses

    - `AlphaFactorScore`: name, sub_score (Decimal, -5 to +5), raw_value (Optional[Decimal]), weight (Decimal), base_weight (Decimal), quality (str: "live"|"cached"|"stale"|"unavailable"|"warmup"), description (str)

    ## Factor 1: Z-Score Mean Reversion (SCORE-01)

    `compute_zscore_mean_reversion(prices: List[Decimal], window: int = 60) -> ZScoreResult`

    - Input: XRPBTC close prices (newest last), configurable rolling window (default 60)
    - Computation: rolling mean and std over window, Z = (current - mean) / std
    - Mapping: Z=-3 -> +5 (buy XRP), Z=0 -> 0, Z=+3 -> -5 (sell XRP). Linear, clamped to [-5, +5]
    - Edge cases:
      - len(prices) < window -> quality="warmup", sub_score=0
      - std=0 (constant series) -> sub_score=0, quality="live"
    - All math in Decimal (use Decimal.sqrt() for std, not math.sqrt)

    Cases:
    - 60 prices all equal (Decimal("0.00004")) -> zscore=0, sub_score=0
    - 60 prices where last is 2 std below mean -> sub_score positive (buy signal)
    - 60 prices where last is 2 std above mean -> sub_score negative (sell signal)
    - 30 prices (< window) -> quality="warmup"
    - Empty list -> quality="warmup"

    ## Factor 2: Lead-Lag Momentum (SCORE-02)

    `compute_leadlag_momentum(btc_returns: List[Decimal], xrp_returns: List[Decimal], window: int = 30, max_lag: int = 10) -> LeadLagResult`

    - Input: Aligned return series for BTCEUR and XRPBTC (same length, same timestamps)
    - Computation: Cross-correlate BTCEUR returns with XRPBTC returns at lags 1..max_lag
    - Signal: If BTC moved strongly (return > 1 std dev of recent returns) and XRP lagged (lag > 0, correlation > threshold), sub_score is positive (buy XRP anticipating catch-up)
    - Mapping: Correlation magnitude and BTC move strength to -5..+5
    - Edge cases:
      - len < window -> quality="warmup"
      - No significant correlation at any lag -> sub_score=0
      - All returns zero -> sub_score=0

    Cases:
    - BTC up 5%, XRP flat, high correlation at lag 2 -> positive sub_score
    - BTC down 5%, XRP flat, high correlation at lag 2 -> negative sub_score
    - No correlation -> sub_score near 0
    - Insufficient data -> quality="warmup"

    ## Factor 3: Orderbook Imbalance (SCORE-03)

    `compute_orderbook_imbalance(bids: List[tuple[Decimal, Decimal]], asks: List[tuple[Decimal, Decimal]], mid_price: Decimal, band_pct: Decimal = Decimal("0.01")) -> OrderbookImbalanceResult`

    - Input: Bid/ask lists as [(price, qty), ...], mid price, band percentage (1% = 0.01)
    - Computation: Sum bid volume within band vs ask volume within band. Imbalance = (bid_vol - ask_vol) / (bid_vol + ask_vol)
    - Mapping: Imbalance ratio (-1 to +1) to sub_score (-5 to +5). Linear.
    - Edge cases:
      - Empty orderbook -> quality="unavailable", sub_score=0
      - All volume on one side -> sub_score=+5 or -5
      - Total volume = 0 within band -> sub_score=0

    Cases:
    - 70% bid / 30% ask within 1% band -> positive sub_score (buy pressure)
    - 30% bid / 70% ask within 1% band -> negative sub_score (sell pressure)
    - Equal bid/ask -> sub_score=0
    - Empty lists -> quality="unavailable"

    ## Factor 4: Funding Rate Score (SCORE-04)

    `compute_funding_rate_score(funding_rate: Optional[Decimal], btc_funding: Optional[Decimal] = None) -> FundingRateResult`

    - Input: Current funding rate for target asset (e.g., XRP-USDT-SWAP from OKX). Optional BTC funding for relative comparison.
    - Computation: High positive funding = overleveraged longs = sell signal. High negative funding = overleveraged shorts = buy signal. With BTC reference: relative divergence adds signal.
    - Mapping: funding_rate to sub_score. Negative funding (shorts paying) -> positive sub_score (contrarian buy). Positive funding (longs paying) -> negative sub_score (contrarian sell). Scale: |rate| >= 0.1% maps to +/-5.
    - Edge cases:
      - None funding -> quality="unavailable", sub_score=0
      - funding=0 -> sub_score=0

    Cases:
    - funding_rate=Decimal("0.0005") (positive, longs paying) -> negative sub_score
    - funding_rate=Decimal("-0.0005") (negative, shorts paying) -> positive sub_score
    - funding_rate=None -> quality="unavailable"
    - funding_rate=Decimal("0") -> sub_score=0
