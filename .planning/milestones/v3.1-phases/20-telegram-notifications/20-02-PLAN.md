    **Add import** at the top of the file (after existing service imports):
    ```python

    ```

    **Modify `_run_all_checks()`** — add notification hook AFTER the result dict is assembled, BEFORE the return statement:

    ```python
    async def _run_all_checks(self) -> dict:
        # ... existing parallel checks ...

        overall = compute_overall_status(statuses)

        result = {
            "overall_status": overall,
            "services": {name: asdict(s) for name, s in statuses.items()},
            "checked_at": now_iso,
        }

        # Notify on state transitions (TELE-01)
        try:
            notifier = get_telegram_notifier()
            await notifier.check_transitions(result)
        except Exception:
            logger.exception("TelegramNotifier.check_transitions() failed")

        return result
    ```

    IMPORTANT design points:
    - The notification call is wrapped in try/except so Telegram failures NEVER prevent health check responses from being returned (anti-pattern from research: "Blocking health check on Telegram send failure")
    - The notifier is retrieved via `get_telegram_notifier()` (singleton) — no constructor call, no new instance per check
    - If the notifier is disabled (no env vars), `check_transitions()` returns immediately (no-op)
    - The logger.exception catches edge cases where the notifier singleton itself fails

    Do NOT modify `get_health()` — the notification hook belongs in `_run_all_checks()` which is only called when the cache expires. This means notifications fire at most once per 5-second cache TTL, which is the correct rate.
