## Goal

User can see orderblock zones rendered as shaded rectangular overlays on the dedicated Chart page, and their portfolio break-even price as a labeled horizontal line. Zones are fetched for the current symbol and chart interval. Break-even comes from the existing portfolio endpoint. Both overlays are toggleable via buttons in the existing floating toolbar.

## Context

### User Decisions (from 26-CONTEXT.md -- NON-NEGOTIABLE)

- Show UNMITIGATED + MITIGATED zones (not INVALID)
- UNMITIGATED zones at full opacity, MITIGATED zones dimmed/faded
- Zones are shaded rectangles between zone_top and zone_bottom
- Conviction-based styling (higher conviction = more opaque)
- Zone direction coloring: bullish green, bearish red
- All overlays on by default
- Each overlay type individually toggleable via buttons in the floating toolbar
- Toggle buttons added to the existing toolbar (alongside interval/lookback controls)
- Break-even line: choose best style based on chart theme

### Existing Code to Reuse

- `Chart.jsx` already has `chartRef`, `candleSeriesRef`, `volumeSeriesRef`, floating toolbar with interval/lookback groups
- `OrderblockChart.jsx` has the exact pattern for `createPriceLine()`, `priceLinesRef`, cleanup in useEffect return
- `useChartTheme` provides `profit` (green), `loss` (red), `accentOrderblock` (amber), `accentBlue`, `hexToRgb()`
- `LineStyle` from lightweight-charts: Solid, Dashed, Dotted, SparseDotted
- `getOrderblockZones(userId, { symbol, interval, state })` in `client.js` -- fetches zones
- `getPortfolio(userId, marketPrice, symbol)` in `client.js` -- returns `break_even` field
- `useSymbol()` and `useUser()` contexts available in Chart.jsx

### Zone Rendering Strategy

lightweight-charts does not have native rectangle/area overlays. The standard approach is to use **two horizontal price lines** (zone_top and zone_bottom) per zone to indicate the zone boundaries. This is the same pattern used by `OrderblockChart.jsx` and provides clear visual zone boundaries with axis labels. Higher conviction zones get thicker lines to stand out.

### Break-Even Data

The portfolio endpoint requires a `market_price` parameter. Since the Chart page does not have a live ticker price, use a simple approach: fetch the break-even once using the latest candle's close price as `market_price`. The break-even value itself is independent of market_price (it is `cost_basis / qty`), so the exact market_price parameter only affects other portfolio KPIs, not break-even. Refetch when candle data changes.

<task id="26-01-T2" title="Render orderblock zone overlays and break-even line on the chart">

**File:** `frontend/src/components/Chart.jsx`

Add a useEffect that draws zone overlays and break-even line on the candle series using `createPriceLine()`. Follow the exact cleanup pattern from `OrderblockChart.jsx`.

**Add this useEffect after the existing "Data update" useEffect (the one that calls `candleSeriesRef.current.setData`):**

```js
// ---- Overlay rendering (zones + break-even) ----
useEffect(() => {
  const series = candleSeriesRef.current;
  if (!series) return;

  // Clean up previous overlay lines
  overlayLinesRef.current.forEach((pl) => {
    try { series.removePriceLine(pl); } catch (_) { /* ignore */ }
  });
  overlayLinesRef.current = [];

  // --- Orderblock Zones ---
  if (showZones && zonesData?.zones) {
    const visibleZones = zonesData.zones.filter(
      (z) => z.state === 'UNMITIGATED' || z.state === 'MITIGATED'
    );

    for (const zone of visibleZones) {
      const isBullish = zone.direction === 'BULLISH';
      const baseColor = isBullish ? theme.profit : theme.loss;
      const isMitigated = zone.state === 'MITIGATED';

      // Conviction-based line width: LOW=1, STANDARD=1, HIGH=2, INSTITUTIONAL=3
      const convictionWidth = zone.conviction === 'INSTITUTIONAL' ? 3
        : zone.conviction === 'HIGH' ? 2 : 1;

      // Opacity: UNMITIGATED full, MITIGATED dimmed
      const alpha = isMitigated ? 0.35 : 0.7;
      const lineColor = `rgba(${hexToRgb(baseColor)}, ${alpha})`;

      // Zone top line
      overlayLinesRef.current.push(
        series.createPriceLine({
          price: parseFloat(zone.zone_top),
          color: lineColor,
          lineWidth: convictionWidth,
          lineStyle: LineStyle.Dashed,
          axisLabelVisible: false,
          title: '',
        })
      );

      // Zone bottom line
      overlayLinesRef.current.push(
        series.createPriceLine({
          price: parseFloat(zone.zone_bottom),
          color: lineColor,
          lineWidth: convictionWidth,
          lineStyle: LineStyle.Dashed,
          axisLabelVisible: false,
          title: '',
        })
      );
    }
  }

  // --- Break-Even Line ---
  if (showBreakEven && portfolioData?.break_even) {
    const bePrice = parseFloat(portfolioData.break_even);
    if (bePrice > 0 && isFinite(bePrice)) {
      overlayLinesRef.current.push(
        series.createPriceLine({
          price: bePrice,
          color: theme.accentBlue,
          lineWidth: 2,
          lineStyle: LineStyle.Dotted,
          axisLabelVisible: true,
          title: 'Break-Even',
        })
      );
    }
  }

  return () => {
    overlayLinesRef.current.forEach((pl) => {
      try { series.removePriceLine(pl); } catch (_) { /* ignore */ }
    });
    overlayLinesRef.current = [];
  };
}, [showZones, showBreakEven, zonesData, portfolioData, candles, theme]);
```

**Key design decisions:**
- Zone lines use `axisLabelVisible: false` to avoid cluttering the price axis with many zone labels (there could be 10+ zones)
- Break-even uses `axisLabelVisible: true` with title "Break-Even" since there is exactly one
- Break-even uses `accentBlue` (#60a5fa) with Dotted style -- clearly distinct from zone lines (Dashed) and candle colors
- Conviction maps to line width for visual hierarchy without needing labels
- MITIGATED zones at 35% alpha vs UNMITIGATED at 70% alpha

**Verify:** Zones appear as paired dashed lines (top/bottom). Break-even appears as a blue dotted line with "Break-Even" label on the price axis. Toggling `showZones` or `showBreakEven` to false removes the respective overlays.

</task>
