<objective>
Introduce per-fill result tracking in the sync pipeline so every fill gets an explicit outcome (processed/failed/skipped) and the sync response provides a resumption watermark.

Purpose: SYNC-01 requires no silent skips -- every fill must be accountable. SYNC-03 requires trackable progress with resumption capability. SYNC-02 (automatic retry of transient errors) was implemented by Phase 5's `@retry_on_transient_error` on `_fetch_trades_page` -- this plan adds a verification test confirming the wiring reaches sync_fills end-to-end. Currently, sync_fills catches errors per-fill but only appends to a flat `errors` list without identifying which specific fills succeeded or failed.

Output: SyncResult domain model, refactored sync_fills with per-fill tracking, SYNC-02 retry wiring verification test, comprehensive TDD test suite.
</objective>

    ## Domain Model: backend/app/domain/sync_result.py

    Create pure dataclasses (no I/O, Decimal precision):

    **FillOutcome** (str enum):
    - `PROCESSED` - Fill successfully persisted + lot created or sell allocated
    - `FAILED` - Fill persisted as ledger event but lot/allocation creation failed
    - `SKIPPED_FIFO` - Fill skipped because a prior FIFO allocation failed (preserves FIFO invariant)
    - `SKIPPED_DUPLICATE` - Fill already existed in DB (idempotency filter)

    **FillResult** (dataclass):
    - `source_id: str` - Binance trade ID
    - `fill_id: str` - Internal ledger event ID (e.g., "binance_BTCEUR_12345")
    - `side: str` - "BUY" or "SELL"
    - `outcome: FillOutcome`
    - `error: str | None` - Error message if FAILED
    - `timestamp: datetime | None` - Fill timestamp (for watermark computation)

    **SyncResult** (dataclass):
    - `fills_total: int` - Total fills fetched from Binance
    - `fills_new: int` - New fills after idempotency filter
    - `fills_processed: int` - Successfully processed (lot created or sell allocated)
    - `fills_failed: int` - Persisted but processing failed
    - `fills_skipped_fifo: int` - Skipped due to FIFO abort
    - `new_lots: int` - Buy lots created
    - `allocations: int` - Sell allocations created
    - `fill_results: list[FillResult]` - Per-fill detail
    - `last_synced_source_id: str | None` - Highest source_id of successfully processed fill (watermark for resumption)
    - `fifo_aborted: bool` - Whether FIFO abort occurred
    - `status: str` - Computed property: "success" | "partial_success" | "fifo_error" | "no_new_fills"
    - `to_dict() -> dict` - Serializes to API-compatible dict. Per-fill detail only for FAILED and SKIPPED_FIFO fills (keep response compact). Includes summary counts, status, last_synced_source_id, errors list (backward compat), and a `fill_details` list with failed/skipped fills.

    Computed properties:
    - `status` returns "no_new_fills" if fills_new==0, "fifo_error" if fifo_aborted, "partial_success" if fills_failed>0, else "success"
    - `errors` returns list of error strings from failed FillResults (backward compat with existing response format)

    **to_dict() output format** (backward compatible + new fields):
    ```python
    {
        "status": "partial_success",
        "new_fills": 5,           # backward compat
        "new_lots": 3,            # backward compat
        "allocations": 1,         # backward compat
        "errors": ["Error creating lot from buy fill X: ..."],  # backward compat
        "message": "Synced 5 fills...",  # backward compat
        # New fields:
        "fills_processed": 4,
        "fills_failed": 1,
        "fills_skipped_fifo": 0,
        "last_synced_source_id": "99887",
        "fifo_aborted": false,
        "fill_details": [         # Only FAILED + SKIPPED_FIFO fills
            {"source_id": "123", "fill_id": "binance_BTCEUR_123", "side": "BUY", "outcome": "FAILED", "error": "..."}
        ]
    }
    ```

    ## Refactored sync_fills: backend/app/services/sync_service.py

    Refactor `sync_fills()` to build a `SyncResult` internally and return `sync_result.to_dict()`.

    Changes:
    1. After `_filter_new_fills()`, record SKIPPED_DUPLICATE fills (just count, no FillResult needed -- they never appear in response)
    2. In Phase 1 (Buy lots): For each buy fill, create a `FillResult(outcome=PROCESSED)` on success or `FillResult(outcome=FAILED, error=str(e))` on failure
    3. In Phase 2 (Sell allocation): For each sell fill, create `FillResult(outcome=PROCESSED)` on success, `FillResult(outcome=FAILED, error=str(e))` on failure. On FIFO abort: mark remaining sells as `FillResult(outcome=SKIPPED_FIFO)`
    4. Compute `last_synced_source_id` as `max(source_id for fr in fill_results if fr.outcome == PROCESSED)` (numeric comparison since Binance trade IDs are integers)
    5. Return `sync_result.to_dict()` -- backward compatible with existing consumers (same keys: status, new_fills, new_lots, allocations, errors, message)

    IMPORTANT: The return type is still `Dict[str, Any]` -- no API route changes needed. The dict just has additional keys.
