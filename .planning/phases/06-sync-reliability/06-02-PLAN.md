  <action>
    Update the two sync endpoints in `sync.py` to properly handle and propagate the new structured response from `sync_service.sync_fills()`:

    **1. `POST /api/sync/{user_id}/fills` (sync_fills endpoint):**
    - No change needed -- it already returns `sync_service.sync_fills(...)` directly, and Plan 01 changes the dict output to include the new fields. Just verify it passes through correctly.

    **2. `POST /api/sync/{user_id}/fills/full` (sync_all_fills endpoint):**
    - This endpoint calls `sync_service.sync_fills()` in a loop (up to 10 batches). Currently it accumulates `total_new_fills`, `total_new_lots`, `total_allocations` across batches.
    - Add accumulation of new fields across batches:
      - `total_fills_processed += result.get("fills_processed", 0)`
      - `total_fills_failed += result.get("fills_failed", 0)`
      - `total_fills_skipped_fifo += result.get("fills_skipped_fifo", 0)`
      - `all_fill_details.extend(result.get("fill_details", []))` -- aggregate failed/skipped fill details from all batches
      - `last_synced_source_id = result.get("last_synced_source_id")` -- update to latest batch's watermark (if not None)
      - `all_errors.extend(result.get("errors", []))` -- aggregate errors across batches
    - Update the fifo_error early return to include the new aggregated fields
    - Update the success return to include:
      ```python
      {
          "status": "success",
          "message": f"Full sync completed: {total_new_fills} fills imported",
          "new_fills": total_new_fills,
          "new_lots": total_new_lots,
          "allocations": total_allocations,
          "fills_processed": total_fills_processed,
          "fills_failed": total_fills_failed,
          "fills_skipped_fifo": total_fills_skipped_fifo,
          "last_synced_source_id": last_synced_source_id,
          "fifo_aborted": False,
          "fill_details": all_fill_details,
          "errors": all_errors,
      }
      ```
    - If any batch had fills_failed > 0 but no fifo_error, set status to "partial_success"
  </action>
