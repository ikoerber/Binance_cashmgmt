  <files>backend/app/db/models.py, backend/app/services/pairing_service.py, backend/alembic/versions/</files>
  <action>
    **DB models (db/models.py):**
    - Add `base_asset = Column(String, nullable=True)` to PairingDB (after `symbol` column)
    - Add `cost_eur = Column(Numeric(precision=20, scale=10), nullable=True)` to PairingItemDB (after `cost_quote`)
    - Add `lot_symbol = Column(String, nullable=True)` to PairingItemDB (after `cost_eur`)

    **Alembic migration:**
    - Run `cd /Users/ikoerber/AIProjects/cashmgnt/backend && alembic revision --autogenerate -m "add_cross_pair_pairing_columns"`
    - Clean up autogenerated migration to only include new columns (remove false positive SQLite type changes if any, per Phase 2 pattern)
    - Migration uses `batch_alter_table` for SQLite compatibility (render_as_batch=True already configured)
    - Existing pairings get NULL for base_asset (no backfill needed -- single-pair pairings remain as-is)
    - Apply: `alembic upgrade head`

    **Service layer (pairing_service.py):**

    1. `get_pairing_suggestions()`: Add `base_asset: str | None = None` parameter.
       - When `base_asset` is provided: import `get_symbols_for_base_asset` from `app.symbol_registry`, query lots with `TradeLotDB.symbol.in_(symbols)`, validate all lots have `cost_eur is not None` (raise ValueError if any lack it), call `suggest_pairings(lots_domain, market_price, threshold_pct, use_eur_cost=True)`
       - When `base_asset` is None: existing single-symbol path unchanged
       - `market_price` MUST be in EUR when `base_asset` is provided (caller responsibility, documented)

    2. `_pairing_to_dict()`: Extend to include `base_asset`, `is_cross_pair`, and per-item `cost_eur` + `lot_symbol` fields in the response dict. Also include `net_cost_eur` when available.

    3. `_pairing_db_to_domain()`: Map `base_asset` from PairingDB. Map `cost_eur` and `lot_symbol` from PairingItemDB.

    4. `create_pairing()`: Add `base_asset: str | None = None` parameter. When provided, set `pairing_db.base_asset = base_asset`. Compute and persist `cost_eur` and `lot_symbol` on PairingItemDB (cost_eur from the lot's cost_eur proportional to qty, lot_symbol from lot's symbol).

    5. `simulate_pairing_execution()`: Add `xrpbtc_price: Decimal | None = None` and `btceur_price: Decimal | None = None` parameters. When both are provided AND the pairing has `base_asset`, compute `DualRouteComparison` via `compute_dual_route_comparison()` and add it to the response dict as `dual_route_comparison` (serialized with string Decimals). When not provided, omit `dual_route_comparison` (backward compatible).

    6. `list_pairings()`: Add `base_asset: str | None = None` parameter. When provided, filter by `PairingDB.base_asset == base_asset`. This enables listing all cross-pair pairings for a given base asset.

    **Import additions in pairing_service.py:**
    - `from app.symbol_registry import get_symbols_for_base_asset`
    - `from app.domain.pairing import compute_dual_route_comparison` (in addition to existing imports)
  </action>
