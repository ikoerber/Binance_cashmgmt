<feature>
  <name>Cross-Pair Pairing Domain Logic</name>
  <files>backend/app/domain/models.py, backend/app/domain/pairing.py, backend/tests/test_cross_pair_pairing.py</files>
  <behavior>
    **Model extensions (models.py):**
    1. PairingItem: add `cost_eur: Optional[Decimal] = None` and `lot_symbol: Optional[str] = None` fields
    2. Pairing: add `base_asset: Optional[str] = None` field, add `is_cross_pair` property (returns `base_asset is not None`), add `net_cost_eur()` method (sums item.cost_eur, returns None if any missing)
    3. New dataclasses: `RouteDetails(symbol, sell_price, gross_proceeds_eur, fees_eur, net_proceeds_eur, conversion_rate, fee_steps)` and `DualRouteComparison(route_direct, route_indirect, recommended_route, eur_difference)`

    **Heuristic extension (pairing.py -- suggest_pairings):**
    Add `use_eur_cost: bool = False` parameter.
    - When `use_eur_cost=False` (default): existing behavior exactly unchanged, uses `lot.break_even * lot.qty_base_open` for cost
    - When `use_eur_cost=True`: validates all lots have `cost_eur is not None` (raises ValueError otherwise), uses `lot.cost_eur` for cost (not `lot.break_even * lot.qty_base_open`), uses `market_price * lot.qty_base_open` for value (market_price is always EUR in this mode)
    - Cross-pair pairings set `base_asset` from lots' base_asset (derived from lot.symbol via `get_base_asset()`), set `symbol` to first lot's symbol
    - PairingItem.cost_eur and PairingItem.lot_symbol are populated in cross-pair mode

    **Dual-route comparison (pairing.py -- new function):**
    `compute_dual_route_comparison(total_base, xrpeur_price, xrpbtc_price, btceur_price, fee_pct=Decimal("0.001"))` returns `DualRouteComparison`:
    - Route direct: `gross = total_base * xrpeur_price`, `fees = gross * fee_pct`, `net = gross - fees`
    - Route indirect: `gross_btc = total_base * xrpbtc_price`, `fees_btc = gross_btc * fee_pct`, `net_btc = gross_btc - fees_btc`, `gross_eur = net_btc * btceur_price`, `fees_eur = gross_eur * fee_pct`, `net = gross_eur - fees_eur` (two fee applications)
    - Recommended route: whichever has higher net_proceeds_eur
    - eur_difference: absolute difference between routes

    Test cases (input -> expected):
    - 2 XRPEUR lots + 1 XRPBTC lot, use_eur_cost=True -> pairing uses cost_eur for all, base_asset="XRP"
    - Same lots as above, use_eur_cost=False -> ValueError (mixes currencies silently, but this mode just uses native quote -- caller should not mix)
    - XRPBTC lot with cost_eur=None, use_eur_cost=True -> ValueError
    - All BTCEUR lots, use_eur_cost=False -> identical to current behavior (backward compat)
    - Single profitable lot, use_eur_cost=True -> no pairing (min 2 lots rule preserved)
    - compute_dual_route_comparison with known prices -> correct EUR proceeds for both routes, correct recommended route
    - compute_dual_route_comparison where indirect > direct -> recommended="XRPBTC"
    - compute_dual_route_comparison where direct > indirect -> recommended="XRPEUR"
    - PairingItem.cost_eur populated in cross-pair mode, lot_symbol populated
    - Pairing.net_cost_eur() returns correct sum, or None if any item missing cost_eur
  </behavior>
  <implementation>
    **models.py changes:**
    - Add `cost_eur: Optional[Decimal] = None` and `lot_symbol: Optional[str] = None` to PairingItem (after cost_quote field)
    - Add `base_asset: Optional[str] = None` to Pairing (after symbol field)
    - Add `is_cross_pair` property to Pairing
    - Add `net_cost_eur()` method to Pairing
    - Add `RouteDetails` and `DualRouteComparison` dataclasses at module level

    **pairing.py changes:**
    - Add `use_eur_cost: bool = False` parameter to `suggest_pairings()`
    - Add validation block at top: if `use_eur_cost` and any lot has `cost_eur is None`, raise ValueError
    - Extract cost computation into helper: `_lot_cost(lot, use_eur_cost)` returns `lot.cost_eur` or `lot.break_even * lot.qty_base_open`
    - When building PairingItem: if `use_eur_cost`, set `cost_eur=lot_cost` and `lot_symbol=lot.symbol`
    - When creating Pairing: if `use_eur_cost`, set `base_asset` from `get_base_asset(lots[0].symbol)` (import from symbol_registry)
    - Add `compute_dual_route_comparison()` function (pure, no I/O)
    - Import `get_base_asset` from `app.symbol_registry`

    **CRITICAL: Backward compatibility** -- existing `suggest_pairings(lots, market_price, threshold_pct)` calls with 3 positional args MUST produce identical results. The new `use_eur_cost` parameter defaults to False, preserving all existing behavior.
  </implementation>
