  <action>
Convert all hardcoded hex color values in Orderblock.css (83 hex), LotsTable.css (68 hex), and PairingPanel.css (65 hex) to var() references.

**Method per file:**
1. Read the file and identify every `#[0-9a-fA-F]{3,8}` occurrence
2. Map each hex value to the appropriate CSS variable from index.css :root (use the Color Deduplication Map from 10-RESEARCH.md)
3. Replace every occurrence with `var(--color-{name})`
4. Also convert `rgba()` values that contain hardcoded color components (not shadow-only rgba with black/white bases)
5. Also convert `linear-gradient()` occurrences to use gradient endpoint variables

**Key mappings (from research):**
- `#f8fafc` -> `var(--color-bg-subtle)`
- `#f1f5f9` -> `var(--color-bg-muted)` or `var(--color-table-row-hover)` depending on context
- `#e2e8f0` -> `var(--color-border)`
- `#334155` -> `var(--color-text-dark)`
- `#475569` -> `var(--color-text-body)`
- `#64748b` -> `var(--color-text-secondary)`
- `#1e293b` -> `var(--color-text-primary)`
- `#16a34a` -> `var(--color-profit)`
- `#dc2626` -> `var(--color-loss)`
- `#6366f1` -> `var(--color-accent-pairing)`
- `#d97706` -> `var(--color-accent-orderblock)`
- `#ffffff` -> `var(--color-bg-card)` (for backgrounds) or `var(--color-text-inverse)` (for text)
- `#d1d5db` -> `var(--color-border-input)`
- `#fef3c7` -> `var(--color-warning-bg)`
- `#92400e` -> `var(--color-warning-text)`
- `#fcd34d` -> `var(--color-warning-border)`
- `#1e40af` -> `var(--color-info-text)`
- `#bfdbfe` -> `var(--color-info-border)`
- `#dbeafe` -> `var(--color-badge-blue-bg)` or `var(--color-info-bg)`
- `#f3e8ff` -> `var(--color-badge-purple-bg)`
- `#6b21a8` -> `var(--color-badge-purple-text)`
- `#818cf8` -> `var(--color-accent-indigo)`
- `#eef2ff` -> `var(--color-bg-selected)` or `var(--color-accent-indigo-light)`
- `linear-gradient(135deg, #f8fafc 0%, #f1f5f9 100%)` -> `linear-gradient(135deg, var(--color-gradient-section-start) 0%, var(--color-gradient-section-end) 100%)`

**LotsTable.css special cases:**
- `.order-row-warning { background: #fffbeb !important; }` -> Remove `!important`, use `var(--color-bg-warning-row)`. If specificity is needed, increase selector to `.lots-table .order-row-warning { background: var(--color-bg-warning-row); }`.
- Success/info banners: map to `--color-success-bg/text/border` and `--color-info-bg/text/border`

**PairingPanel.css special cases:**
- `.summary-profit .summary-value { color: var(--color-profit) !important; }` -> Remove `!important`, increase specificity: `.pairing-panel .summary-profit .summary-value { color: var(--color-profit); }`

**Gradient conversions:**
- All `linear-gradient()` with hardcoded hex pairs must use variable endpoints
- Section gradients: `var(--color-gradient-section-start)` / `var(--color-gradient-section-end)`
- Success gradients: `var(--color-gradient-success-start)` / `var(--color-gradient-success-end)`

**rgba() handling:**
- `rgba(0, 0, 0, ...)` shadow values: can stay as-is (shadows are already handled via --shadow-* variables where used, or remain as structural shadows)
- `rgba(99, 102, 241, ...)` (indigo with alpha): convert to use accent variable where possible, or keep if it is a one-off opacity value
- `rgba(22, 163, 74, ...)` (profit green with alpha): keep structural, document for Phase 11

If any color value cannot be mapped to an existing variable from Plan 01, ADD the missing variable to index.css :root AND the [data-theme="dark"] block. This is expected -- the research inventory may have missed some edge cases.

After converting each file, run `grep -c '#[0-9a-fA-F]' frontend/src/components/{File}.css` to confirm zero remaining hex values.
