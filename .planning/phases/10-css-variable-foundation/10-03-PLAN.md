**Step 1: Identify all JSX inline color references**
Run `grep -rn '#[0-9a-fA-F]' frontend/src/components/*.jsx frontend/src/App.jsx 2>/dev/null` to find all hardcoded color strings in JSX files.

**Step 2: Convert static color references to CSS classes**

For each JSX file with hardcoded colors:

**Approach A (preferred for conditional colors):**
```jsx
// BEFORE
style={{ color: value > 0 ? '#16a34a' : '#dc2626' }}

// AFTER - use CSS utility classes
className={value > 0 ? 'text-profit' : 'text-loss'}
```

Add utility classes to index.css (after the [data-theme="dark"] block):
```css
/* Utility classes for JSX conditional colors */
.text-profit { color: var(--color-profit); }
.text-loss { color: var(--color-loss); }
.text-warning { color: var(--color-warning-text); }
.text-info { color: var(--color-info-text); }
.text-muted { color: var(--color-text-muted); }
.bg-profit { background-color: var(--color-profit); }
.bg-loss { background-color: var(--color-loss); }
.bg-warning { background-color: var(--color-warning-bg); }
```

**Approach B (for truly dynamic backend-computed colors):**
Leave `style={{ backgroundColor: data.action_color }}` in CombinedScore.jsx as-is. The `action_color` comes from the backend API and is a runtime-computed value. Document this as a Phase 11 concern -- when dark mode is activated, the backend may need to return dark-mode-appropriate colors, or the frontend will need a mapping layer.

**Step 3: Handle specific patterns**

Common JSX inline color patterns to convert:
- `style={{ color: '#16a34a' }}` -> `className="text-profit"` (or existing component class)
- `style={{ color: '#dc2626' }}` -> `className="text-loss"`
- `style={{ backgroundColor: '#f8fafc' }}` -> add a CSS class with `background-color: var(--color-bg-subtle)`
- `style={{ borderColor: '#e2e8f0' }}` -> add to existing class or create utility

Where a JSX element already has a className, either:
- Extend the existing class in the CSS file to include the color property
- Use template literal: `` className={`existing-class ${value > 0 ? 'text-profit' : 'text-loss'}`} ``

**Step 4: Document deferred inline styles**
Any truly dynamic inline styles that cannot be converted (e.g., `action_color` from backend) must be documented in the SUMMARY.md as deferred to Phase 11.
