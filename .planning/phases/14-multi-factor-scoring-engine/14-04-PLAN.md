  <name>Task 1: AlphaScoreDataService - Singleton with Mixed Refresh + Cache</name>
  <files>backend/app/services/alpha_score_data_service.py</files>
  <action>
    Create `backend/app/services/alpha_score_data_service.py` as a Singleton data service following `sentiment_data_service.py` pattern:

    **Singleton pattern:**
    - Module-level `_instance = None`, `_lock = threading.Lock()`
    - `get_alpha_score_data_service() -> AlphaScoreDataService` factory function
    - Thread-safe initialization

    **Internal state (under threading.Lock):**
    - `_kline_cache: dict[str, CachedValue]` -- keyed by "{symbol}_{interval}" for klines
    - `_depth_cache: dict[str, CachedValue]` -- keyed by symbol for orderbook snapshots
    - `_depth_history: dict[str, deque]` -- last 5 snapshots per symbol for EMA smoothing (Claude's discretion: EMA with alpha=0.4 over last 5 snapshots)
    - `_funding_cache: dict[str, CachedValue]` -- keyed by symbol for funding rates
    - `_trailing_stops: dict[str, TrailingStopState]` -- per-symbol trailing stop state
    - `_warmup_checked: dict[str, bool]` -- track warmup status per symbol+interval

    **TTL strategy (mixed refresh per locked decision):**
    - Klines: TTL = interval duration (15m klines -> 15min TTL). Cached per symbol+interval.
    - Orderbook depth: TTL = 30s (fetch every 30s, store in deque for EMA)
    - Funding rate: TTL = 15min (reuse OKX fetch pattern from SentimentDataService, not SentimentDataService itself)

    **Main method: `get_alpha_score(self, user_id: str, settings: dict) -> dict`**
    1. Parse settings: interval, weights, threshold, windows, Hurst params, ATR multipliers, resume_n
    2. Determine symbols to score: BTCEUR and XRPBTC (and XRPEUR if needed for funding)
    3. **Candle-driven data (Z-Score, Lead-Lag, Hurst):**
       - Fetch XRPBTC klines (200 candles for Z-Score + Hurst lookback)
       - Fetch BTCEUR klines (200 candles for Lead-Lag)
       - Extract close prices as List[Decimal]
       - Compute returns for Lead-Lag cross-correlation
       - Call `compute_zscore_mean_reversion()` with XRPBTC prices
       - Call `compute_leadlag_momentum()` with aligned BTC/XRP returns
       - Call `compute_hurst_rs()` with XRPBTC prices using settings lookback
    4. **Real-time data (Orderbook, Funding):**
       - Fetch XRPBTC orderbook depth (limit=100)
       - Compute EMA of last 5 imbalance values (store snapshots in deque)
       - Call `compute_orderbook_imbalance()` with EMA-smoothed bid/ask
       - Fetch OKX funding rate for XRP-USDT-SWAP (and BTC-USDT-SWAP for relative comparison)
       - Call `compute_funding_rate_score()`
    5. **Regime + Aggregation:**
       - Call `compute_regime_adjusted_weights()` with base weights from settings and Hurst result
       - Build `AlphaFactorScore` list with regime-adjusted weights
       - Call `compute_alpha_score()` to get final score
    6. **Trailing Stops:**
       - Compute ATR from klines for each position symbol (BTCEUR, XRPEUR)
       - Call `update_trailing_stop()` for each symbol with appropriate multiplier
       - Detect data freshness: compare last kline timestamp to now, stale if > 2x interval
    7. **Warmup check (SCORE-08):**
       - If any candle-driven factor has quality="warmup", set overall quality accordingly
       - Return explicit warmup response: `{"status": "warmup", "candles_available": N, "candles_needed": M}` -- do NOT compute a partial score from insufficient data
       - `MIN_WINDOW_SIZE` constant: max(zscore_window, hurst_lookback) determines warmup threshold
    8. **Graceful degradation (SCORE-07):**
       - Each data fetch wrapped in try/except
       - Failed fetch -> factor gets quality="unavailable", sub_score=0
       - Weights renormalized across available factors (handled by domain function)
       - Quality badges: "live" (fresh data), "cached" (within TTL), "stale" (>6x TTL), "unavailable" (fetch failed)
    9. **Serialization:**
       - All Decimal values serialized as strings
       - Trailing stop frozen state includes `frozen_since` as ISO timestamp and `data_points_needed`
       - Regime info includes Hurst value, label, confidence, and current Z-Score effective weight percentage

    **OKX Funding Rate fetch:**
    - Reuse the HTTP pattern from SentimentDataService (same OKX endpoint, same response parsing)
    - Do NOT import or call SentimentDataService directly -- own cache, own fetch (per research anti-pattern guidance)
    - Endpoint: `https://www.okx.com/api/v5/public/funding-rate?instId={instId}`
    - instIds: "XRP-USDT-SWAP", "BTC-USDT-SWAP"

    **Orderbook EMA smoothing (Claude's discretion):**
    - Store last 5 orderbook imbalance ratios in a deque per symbol
    - EMA with alpha=0.4: `ema = alpha * new_value + (1 - alpha) * old_ema`
    - Use EMA value as input to `compute_orderbook_imbalance()` scoring (pass synthetic bid/ask that produce the EMA ratio, or refactor scoring to accept ratio directly)
    - Alternative (simpler): compute imbalance ratio from raw bid/ask, then EMA-smooth the ratio, then map to sub_score. This avoids modifying the domain function.

    **Portfolio-aware stop tightening (per CONTEXT.md):**
    - Compute rolling correlation between BTC and XRP returns (using same Lead-Lag window)
    - When correlation > 0.7, multiply ATR distance by `1 - (correlation - 0.7) * 0.5` (max 15% tightening at correlation 1.0)
    - Apply to both BTC and XRP trailing stops
