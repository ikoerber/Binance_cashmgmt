    ## Function 1: Hurst Exponent via R/S Analysis (SCORE-09)

    `compute_hurst_rs(prices: List[Decimal], min_window: int = 10) -> HurstResult`

    - Rescaled Range (R/S) Analysis per user decision (not DFA or other methods)
    - Compute returns from prices, then for multiple sub-window sizes (powers of 2), compute R/S statistic
    - Log-log regression of R/S vs window size gives Hurst exponent as slope
    - Regime classification: H > 0.55 = trending, H < 0.45 = mean_reverting, 0.45-0.55 = transitional (per locked decisions)
    - Confidence from R-squared of the log-log regression
    - Edge cases:
      - Less than min_window*2 data points -> H=0.5, regime="transitional", confidence=0
      - Constant series (std=0 in all segments) -> H=0.5, regime="transitional", confidence=0
      - Very few window sizes (< 2) -> H=0.5, confidence=0

    Cases:
    - Random walk data (shuffled) -> H near 0.5
    - Trending data (monotonic + noise) -> H > 0.55
    - Mean-reverting data (oscillating) -> H < 0.45
    - 15 data points (< min_window*2) -> H=0.5, confidence=0
    - All same price -> H=0.5, confidence=0

    ## Function 2: Regime-Adjusted Weight Redistribution (SCORE-09)

    `compute_regime_adjusted_weights(base_weights: dict, hurst: Decimal, trending_threshold: Decimal = Decimal("0.55"), reverting_threshold: Decimal = Decimal("0.45")) -> dict`

    - Per locked decision: gradual blend, NOT binary switch
    - H <= 0.45: Z-Score gets full base weight (no change)
    - H >= 0.55: Z-Score weight reduced to 0, freed weight distributed: Lead-Lag 60%, Imbalance 30%, Funding 10%
    - 0.45 < H < 0.55: Linear interpolation of reduction percentage
    - Output weights must sum to 1.0 (within Decimal tolerance)
    - Normalization step at end to handle rounding

    Cases:
    - H=0.40 -> weights unchanged from base
    - H=0.45 -> weights unchanged (boundary)
    - H=0.50 -> Z-Score reduced by 50% of base, freed weight redistributed 60/30/10
    - H=0.55 -> Z-Score = 0, full redistribution
    - H=0.70 -> same as 0.55 (clamped at threshold)
    - Weights sum to 1.0 in all cases

    ## Function 3: Alpha Score Composite (SCORE-05)

    `compute_alpha_score(factors: List[AlphaFactorScore], regime: RegimeInfo, threshold: Decimal = Decimal("3.0"), timestamp: datetime = None) -> AlphaScoreResult`

    - Weighted sum of factor sub_scores using regime-adjusted weights
    - Clamp final score to [-5, +5]
    - Trade signal: score >= threshold -> "LONG", score <= -threshold -> "SHORT", else "NEUTRAL"
    - Quality: all 4 live -> "full", 3 live -> "partial", 1-2 live -> "degraded", 0 live -> "warmup"
    - Active factors = count of factors with quality != "unavailable" and quality != "warmup"
    - When factors are unavailable: renormalize remaining weights to sum to 1.0

    Cases:
    - All 4 factors with sub_scores [+3, +2, +1, +1], base weights -> weighted score, signal depends on threshold
    - Score = +4.0, threshold = 3.0 -> signal = "LONG"
    - Score = -4.0, threshold = 3.0 -> signal = "SHORT"
    - Score = +1.5, threshold = 3.0 -> signal = "NEUTRAL"
    - 1 factor unavailable -> renormalize 3 remaining weights, quality = "partial"
    - All factors warmup -> quality = "warmup", score = 0

    ## Function 4: ATR Trailing Stop (EXIT-01, EXIT-02)

    `compute_atr(candles: List[dict], period: int = 14) -> Optional[Decimal]`
    - Reuse Wilder's Smoothing pattern from orderblock.py. If `compute_atr` already exists in a reusable location, import it. Otherwise, implement following the same Wilder's formula.
    - Input: list of candle dicts with "high", "low", "close" as Decimal
    - Edge case: fewer than period+1 candles -> None

    `update_trailing_stop(state: TrailingStopState, current_price: Decimal, current_atr: Decimal, multiplier: Decimal, data_is_fresh: bool, now: datetime) -> TrailingStopState`
    - Ratchet: stop only moves in favorable direction (up for longs, down for shorts)
    - ATR floor: stop never closer than ATR * multiplier to current price
    - Freeze: when data_is_fresh=False, set frozen=True, hold stop_level
    - Resume: after N consecutive fresh data points (resume_threshold), unfreeze and resume normal computation
    - Hybrid: ratchet + ATR floor means stop = max(old_stop, price - ATR*mult) for longs

    Cases:
    - Long position, price rises -> stop ratchets up
    - Long position, price drops -> stop holds (never goes down)
    - Short position, price drops -> stop ratchets down
    - Data gap (data_is_fresh=False) -> frozen=True, stop unchanged
    - Resume: 5 consecutive fresh data points -> frozen=False
    - Resume: 4 fresh then 1 stale -> counter resets
    - Initial state (stop_level=None) -> first update sets stop
