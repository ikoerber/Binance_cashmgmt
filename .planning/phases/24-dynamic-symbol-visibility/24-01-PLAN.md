Create `backend/app/api/routes/balances.py` with a new FastAPI router.

**Endpoint:** `GET /api/balances/{user_id}/active-symbols`

**Logic:**
1. Import `BinanceService` and `KNOWN_PAIRS` from `app.symbol_registry`.
2. Call `BinanceService().fetch_account_balance()` to get `{asset: {free, locked, total}}`.
3. Define a dust threshold: `Decimal("0.00000001")` — any balance above this counts as "holding". This filters Binance dust (sub-satoshi remainders) while keeping any meaningful position.
4. Build the active symbols list by iterating `KNOWN_PAIRS`:
   - For each pair, check if the pair's `base_asset` has a balance above the dust threshold.
   - **XRPBTC special rule (LOCKED DECISION):** Include XRPBTC when user holds XRP, regardless of BTC balance. This means: if XRP balance > dust threshold, include both XRPEUR and XRPBTC.
5. **Fallback (zero assets):** If no symbols qualify, return `["BTCEUR"]` as the default fallback so the UI always has at least one symbol.
6. Return JSON: `{"active_symbols": ["BTCEUR", "XRPEUR", "XRPBTC"], "balances": {"BTC": "0.01234", "XRP": "100.50", "EUR": "1500.00"}}`. Include string-serialized balances for debug/display but the primary field is `active_symbols` (list of symbol strings matching KNOWN_PAIRS keys).

**Error handling:** Wrap the Binance call in try/except. On failure, log via `logger.exception()` and return `{"active_symbols": list(KNOWN_PAIRS.keys()), "balances": {}, "error": "Balance fetch failed"}` — graceful degradation showing all symbols rather than none.

Follow existing route patterns: `router = APIRouter(prefix="/api/balances", tags=["balances"])`, use `logger = logging.getLogger(__name__)`.

**2. Create `frontend/src/hooks/useActiveSymbols.js`:**

```javascript
import { useQuery } from '@tanstack/react-query';
import { getActiveSymbols } from '../api/client';
import { useUser } from '../contexts/UserContext';
import { getAllSymbols } from '../utils/symbolRegistry';

/**
 * Returns the list of symbols the user actually holds on Binance.
 * Falls back to all symbols on error or while loading.
 *
 * Refresh: 60s polling — balance changes are infrequent (fills, deposits).
 * The WebSocket balance_update event will invalidate this query for faster updates.
 */
export function useActiveSymbols() {
  const { userId } = useUser();

  const { data, isLoading, isError } = useQuery({
    queryKey: ['active-symbols', userId],
    queryFn: () => getActiveSymbols(userId),
    staleTime: 30_000,        // 30s stale — balance changes are rare
    refetchInterval: 60_000,  // 60s polling — low frequency, balance-driven
    retry: 2,
  });

  // While loading or on error: show all symbols (graceful degradation)
  const activeSymbols = data?.active_symbols || getAllSymbols();

  return { activeSymbols, isLoading, isError };
}
```

**Key design decisions (Claude's discretion):**
- **60s polling** — Balances change infrequently (on fills or deposits). Combined with WebSocket invalidation, this is sufficient.
- **Fallback to all symbols** during loading/error — prevents flickering empty nav on page load.
- **30s staleTime** — shared across GlobalNav and Overview consumers without double-fetching.
